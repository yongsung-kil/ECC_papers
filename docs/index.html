AI 에이전트 1. Prime ECC 최적화

원본 C++ 코드를 기능은 그대로 둔 채 구조만 다시 짜고, 실험용 경량판을 갈라냈습니다.

측정 예정
SPEED GAIN

원본은 사람이 만든 C++ 코드이며, 이 갈래의 첫 조건은 기능을 바꾸지 않는 것입니다. 손대기 전에 원본이 내는 결과를 기준으로 잡고, 고친 뒤에도 같은 결과가 나오는지 확인합니다.

그 위에서 속도와 메모리를 함께 봅니다. 하드웨어 구현에 맞물린 부분은 건드리지 않습니다.

같은 뼈대에서 Python 경량판을 갈라냈습니다. C++은 아이디어를 붙였다 떼기에 무거워서, 실험은 경량판에서 하고 결과만 이쪽으로 가져옵니다.

에이전트 3에서 검증이 끝난 알고리즘은 이 갈래로 돌아와 원본에 반영되고, 적용한 뒤 한 번 더 최적화를 거칩니다. 그 과정에서 나온 결과와 시행착오는 기록으로 남아 다음 시도의 재료가 됩니다.

AI 에이전트 2. 논문과 특허 분석

LDPC 논문 22,225편을 한 편씩 읽고, 적용해볼 만한 2,783편을 남겼습니다.

IEEE 저널과 학회에서 21,101편, arXiv에서 1,124편을 모았습니다. 합쳐서 22,225편입니다.

1차로 주제와 기여가 우리 문제에 닿는지를 보아 6,222편을 남겼습니다. 이 단계는 전량을 대상으로 하며 걸러진 논문도 판정 근거를 함께 남깁니다.

2차로 실제 적용 가능성을 네 가지 기준으로 다시 걸렀습니다. 하드 판정 1비트, 내부 양자화, 부호율 0.8 이상, 코드 길이 2KB 이상이며, 넷 중 하나라도 맞으면 남깁니다. 그 결과가 2,783편입니다.

남은 논문은 사이드바의 논문 탐색기에서 조건을 걸어 찾아볼 수 있습니다. 특허는 같은 방식으로 넓힐 예정이며 아직 하지 않았습니다.

AI 에이전트 3. 아이디어 구현

고른 아이디어를 경량판에 붙여 성능을 재고, 나아진 것만 원본으로 넘깁니다.

1.9배
LIGHT VS ORIGINAL

바탕은 원본에서 갈라낸 Python 경량판입니다. 원본보다 1.9배 빠릅니다. numpy로 프레임을 묶어 한 번에 처리하고, 하드웨어 구현용 파이프라인을 뺐기 때문입니다. 정정 능력은 원본과 비슷합니다.

에이전트 2가 고른 논문에서 아이디어를 하나씩 꺼내 경량판에 붙입니다. 붙인 뒤에는 정정 성능과 처리량을 기존과 견줍니다.

나아진 것만 남기고 나머지는 버립니다. 버린 것도 왜 안 됐는지를 함께 기록해 두어, 다음에 비슷한 시도를 다시 하지 않게 합니다.

남은 아이디어는 에이전트 1로 넘어가 원본에 반영됩니다. 원본에 손대는 것은 이 검증을 통과한 것뿐입니다.
